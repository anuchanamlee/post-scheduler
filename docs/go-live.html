เปิดใช้งานจริง post-scheduler

ระบบทำงานครบทุกอย่างอยู่แล้ว แต่ปลายทางยังเป็นของจำลอง — โพสต์ที่ขึ้น “สำเร็จ” ทั้งหมด ขึ้นที่ /mock-feed ไม่ใช่เพจจริง หน้านี้คือลำดับที่ต้องทำเพื่อสลับเป็นของจริง ตรวจสถานะได้ทุกเมื่อด้วย npm run readiness

01

เตรียมบัญชีที่ต้องมีต้องใช้บัญชีของเจ้าของ

ห้าอย่างนี้ผมทำแทนไม่ได้ ต้องเป็นคนที่ถือบัญชีจริงกดเอง เพราะทุกอันออก token ที่ผูกกับตัวตน เริ่มจาก Meta ก่อน เพราะเป็นอันเดียวที่ขาดไม่ได้จริงๆ

บัญชีได้อะไรมาขาดแล้วเป็นยังไงค่าใช้จ่าย
Meta Business Manager + แอปที่ business.facebook.com System User token โพสต์ขึ้นเพจจริงไม่ได้เลย ฟรี
โดเมน + HTTPS (VPS หรือ Cloudflare Tunnel) PUBLIC_BASE_URL Instagram โหลดรูปไม่ได้ → โพสต์ IG ล้มทุกครั้ง ตั้งแต่ฟรี (tunnel) ถึงหลักร้อย/เดือน
Cloudflare R2 / Backblaze B2 / S3 S3_ACCESS_KEY · S3_SECRET_KEY VPS ตายทีเดียว รูปลูกค้าหายหมด R2 ฟรี 10 GB แรก
LINE Official Account (Messaging API) channel access token · userId โพสต์ล้มตอนตี 2 แล้วไม่มีใครรู้ ฟรี
OpenRouter OPENROUTER_API_KEY ผู้ช่วยแคปชั่นและภาพ AI เป็นของจำลอง (ระบบอื่นใช้ได้ปกติ) จ่ายตามใช้ ~$0.04/ภาพ
02

ผูกลูกค้าเข้ากับแอปลูกค้าต้องกดรับเอง

ระบบวิ่งใน Development Mode ซึ่งไม่ต้องผ่าน App Review และไม่ต้อง Business Verification — แต่มีเงื่อนไขเดียวที่ห้ามพลาด: คนที่ใช้แอปต้องมี role บนแอปนั้นจริง ขั้นนี้คือขั้นที่ทำให้ permission ทำงานตามที่เอกสาร Meta เขียนไว้

03

ออก token แล้วตรวจก่อนใช้

Generate token → เลือกแอปที่โอนมา → expiration Never → เลือก 5 permission นี้ แล้วคัดลอกทันที Facebook แสดงให้เห็นครั้งเดียว

Permissionใช้ทำอะไร
pages_manage_postsโพสต์ลงเพจ Facebook
pages_read_engagementอ่านผลตอบรับมาแสดงในหน้า /insights
instagram_basicมองเห็นบัญชี Instagram ที่ผูกกับเพจ
instagram_business_content_publishโพสต์ลง Instagram
business_managementอ่านโครงสร้าง Business Manager
ชื่อ scope ตัว Instagram ยังไม่ยืนยัน — สเปกเดิมบอกว่า instagram_content_publish ถูกแทนที่ด้วย instagram_business_content_publish ตั้งแต่ ม.ค. 2025 แต่ยังไม่เคยตรวจกับ permission reference โดยตรง ถ้าตอน generate ไม่เห็นชื่อนี้ ให้ใช้ชื่อที่ Meta แสดงจริง แล้วบอกผมเพื่ออัปเดตเอกสาร

ตรวจ token ก่อนเอาไปใช้ — อ่านอย่างเดียว ไม่โพสต์อะไร

docker compose exec web npm run verify-meta -- --token "EAAG..." --page <page-id>

สคริปต์จะบอกว่า token มี scope อะไรจริง หมดอายุไหม และมองเห็นเพจไหม — ตอบคำถามเรื่องชื่อ scope ข้างบนไปในตัว

04

เก็บ token เข้าระบบ

token ถูกเข้ารหัส AES-256-GCM ก่อนลงฐานข้อมูลเสมอ คีย์อยู่ใน env ไม่เคยอยู่ในตาราง วิธีที่ง่ายที่สุดคือหน้า /settings → เชื่อมต่อเพจใหม่ ซึ่งเข้ารหัสให้อัตโนมัติ ถ้าจะทำจากบรรทัดคำสั่ง: 

docker compose exec web npx tsx -e "
  import { seal } from './src/lib/crypto.js';
  console.log(JSON.stringify(seal(process.argv[1])));
" 'TOKEN_ที่คัดลอกมา'
ห้ามเปลี่ยน ENCRYPTION_KEY_HEX หลังจากนี้เด็ดขาด — เปลี่ยนเมื่อไหร่ token ของทุกเพจที่เก็บไว้จะถอดไม่ออกอีกเลย ต้องไปออก token ใหม่ทั้งหมด
05

ตั้งค่าเซิร์ฟเวอร์ให้ Meta เข้าถึงได้

Instagram ไม่รับไฟล์อัปโหลด รับแต่ image_url ที่เปิดจากอินเทอร์เน็ตได้จริง — localhost ใช้ไม่ได้ และรูปต้องไม่หายไปพร้อมเครื่อง 

# .env บนเครื่องจริง
PUBLIC_BASE_URL=https://post.ร้านลูกค้า.com

STORAGE_DRIVER=s3
S3_ENDPOINT=https://<account>.r2.cloudflarestorage.com
S3_BUCKET=post-scheduler
S3_ACCESS_KEY=...
S3_SECRET_KEY=...

ยังไม่มีโดเมน ใช้ tunnel ชั่วคราวทดสอบก่อนได้:

cloudflared tunnel --url http://localhost:3000
06

ต่อแจ้งเตือนและตัวเฝ้า worker

ข้อนี้ไม่ใช่ของประดับ — worker ที่ตายแล้วส่งข้อความบอกว่าตัวเองตายไม่ได้ ต้องให้บริการภายนอกสังเกตว่า “ปิงหายไป” แทน (LINE Notify ปิดบริการไปแล้ว 31 มี.ค. 2025 ระบบนี้ใช้ Messaging API) 

NOTIFY_TRANSPORT=line
WORKER_HEARTBEAT_URL=https://hc-ping.com/xxxxxxxx
07

สลับเป็นของจริง แล้วยิงทดสอบ 1 โพสต์

ขั้นนี้คือจุดที่ระบบเริ่มโพสต์ลงเพจจริง ทำหลังจาก 1–6 ผ่านหมดแล้วเท่านั้น 

DEFAULT_PROVIDER=meta
META_APP_SECRET=...
docker compose exec web npm run readiness    # ต้องไม่เหลือข้อ "ยังไม่ได้"
docker compose exec web npm run smoke       # ต้องผ่านทั้งหมด
curl -s https://<โดเมนจริง>/api/health      # ต้องได้ ok:true

แล้วตั้งโพสต์จริง 1 ชิ้น เวลาอีก 5 นาที ดูว่าขึ้นบนเพจจริง — นี่คือหลักฐานเดียวที่นับได้ว่าเชื่อมสำเร็จ

08

เก็บกวาดก่อนส่งมอบ

ข้อแรกคือช่องโหว่จริง ไม่ใช่ความเรียบร้อย — บัญชีตัวอย่างมีรหัสผ่านที่เขียนอยู่ใน README 

docker compose exec web npm run reset-demo   # ล้างโพสต์/แจ้งเตือน/ฟีดจำลอง

สิทธิ์ในระบบ 3 ระดับ

ระดับทำได้ทำไม่ได้
owner ทุกอย่าง — เชื่อม/ตัดเพจ เปลี่ยน token จัดการทีม ตั้งค่าอนุมัติ —
approver เขียนโพสต์ และอนุมัติงานคนอื่น แตะเพจ token หรือทีมงานไม่ได้
editor เขียนโพสต์ — งานเข้าคิวรออนุมัติก่อนขึ้นเพจ อนุมัติงานตัวเองไม่ได้
09

รู้ล่วงหน้าว่าอะไรจะพัง

System User token ตั้ง “Never expire” ได้จริงตามเอกสาร แต่เงื่อนไขที่ทำให้มันพัง Meta ไม่ได้เขียนไว้ที่ไหน — เปลี่ยนรหัสผ่าน · ปิด 2FA · Business Manager ถูกระงับ · ลูกค้าเพิกถอนสิทธิ์ ล้วนทำให้ token ตายได้ ระบบจึงถือว่ามันพังได้เสมอ

สิ่งที่ระบบทำให้เองเมื่อ token ตาย (error 190) — ตั้งสถานะ credential เป็น invalid · หยุดส่งโพสต์ของเพจนั้นทันทีแทนที่จะ retry จนโควตาหมด · แจ้งเตือนระดับ critical · /api/health ตอบ 503 ให้ uptime monitor เห็น

วิธีแก้: ออก token ใหม่ (ทำขั้น 3–4 ซ้ำ) แล้วกด “ส่งเฉพาะช่องทางที่ล้ม” คิวที่ค้างจะเดินต่อเอง
